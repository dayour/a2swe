Executive decision-makers

Microsoft Plugin Architecture: reuse the core, govern each host

Bottom line: standardize skills and MCP, then govern compatibility and ownership for each host.

Decision: Standardize skills and MCP; govern compatibility and ownership per host.

Section 1

1. Choose the host route

Cowork uses a Microsoft 365 app package. Declarative agents use MCP or REST API actions. GitHub Copilot uses plugin packages with portable and client-specific parts.

Supported claims

  • Three host routes use different delivery contracts: Cowork uses Microsoft 365 app packages; declarative agents use MCP or API actions; GitHub Copilot uses plugin packages. [ev-01] [ev-02] [ev-04] [ev-05] [ev-07]
  • Cowork packages skills and connectors in a standard Microsoft 365 app package. [ev-01] [ev-02]
  • Microsoft 365 declarative agents support MCP and REST API plugins as in-agent actions; REST API tools are defined in the plugin manifest. [ev-04] [ev-05] [ev-06]

Assets

Speaker notes

Evidence: the three selected official sources, retrieved 2026-10-06. Decision implication: name the host and package contract for every portfolio item; do not describe these routes as interchangeable.

Section 2

2. Reuse the core, not the wrapper

Reuse skill logic and MCP configuration where tested. Keep authentication, manifests, discovery and client-only components inside each host package.

Supported claims

  • Skills and MCP configuration can be reusable, while manifests, discovery, authentication and client-specific components remain host-specific. [ev-03] [ev-07] [ev-08]

Assets

Speaker notes

Evidence: Cowork skill portability, declarative-agent MCP/API behavior, and GitHub Agent Plugins portability and legacy support. Interpretation: the reusable layer should be separated from host packaging and operations.

Section 3

3. Preserve supported paths

REST API actions remain supported in declarative agents. Agent Plugins 1.0 adds portability, while legacy GitHub Copilot plugins continue to load.

Supported claims

  • Microsoft 365 declarative agents support MCP and REST API plugins as in-agent actions; REST API tools are defined in the plugin manifest. [ev-04] [ev-05] [ev-06]
  • GitHub Agent Plugins 1.0 ports skills and MCP configuration across compatible clients; client-specific components and legacy plugins remain supported. [ev-07] [ev-08] [ev-09]

Assets

Speaker notes

Evidence: Microsoft Learn documents REST API plugins as declarative-agent actions; GitHub documents both Agent Plugins 1.0 and legacy Copilot plugins as supported.

Section 4

4. Govern a small portfolio

Assign one owner per capability and service. Publish a host compatibility matrix, version each package, and add routes only when demand justifies lifecycle cost.

Supported claims

  • Three host routes use different delivery contracts: Cowork uses Microsoft 365 app packages; declarative agents use MCP or API actions; GitHub Copilot uses plugin packages. [ev-01] [ev-02] [ev-04] [ev-05] [ev-07]
  • Skills and MCP configuration can be reusable, while manifests, discovery, authentication and client-specific components remain host-specific. [ev-03] [ev-07] [ev-08]

Assets

Speaker notes

Proposed operating model, grounded in the documented route and compatibility boundaries. No source prescribes an enterprise org chart or ROI target.
