# Power Platform Output Review

As of 2026-09-17. This is a candidate-artifact comparison, not a completed
audiovisual comparison or release approval.

## Findings

1. **Blocking: the requested video does not exist.** The original Microsoft and
   Copilot pilots have rendered MP4s; Power Platform has only a proposed 60-second
   story and 115-word narration. No new frame, audio, pacing, motion, or visual
   quality improvement has been demonstrated. The core rejects production jobs
   and ready DomainPacks until the missing certification implementation exists.
   User unavailability is not approval. This exercise exposes an end-to-end
   product gap rather than establishing a successful agent-to-video workflow.
2. **High: the candidate is not yet a demonstrated SWE executor.** The selectable
   profile declares read/search only. No native-host invocation, repository change,
   code execution, SDK reasoning backend, or tenant integration was tested. It is
   useful for bounded engineering review, but is not evidence of a runnable,
   independently productive implementation agent.
3. **High: initial evaluator grades were unreliable.** Its 31/31 PASS claim is
   rejected. Q08 broadened one operation's wait into delays for all users and
   transactions; Q09 supplied unsupported registration-stage advice; Q14 confused
   ordered promotion with guaranteed QA; E01 confused managed and unmanaged
   uninstall. Most factual answers lacked required URL/locator citations. See the
   complete case disposition below and the preserved raw answers.
4. **High: source traceability is improved, factual certification is incomplete.**
   Seven official source records support 21 bounded claim/evidence pairs. Two
   older foundations remain pending exceptions. Local hashes protect captured
   excerpts, not remote page completeness or factual entailment. Reported Git
   revisions were not independently checked out. Recent documentation dates do
   not establish substantive revision, feature GA, or tenant availability.
5. **Medium: the original visual problems are diagnosed, not fixed on screen.**
   Viewed contact sheets use repeated dark star fields, small supporting labels,
   thin line symbols, and generic connectors. The Copilot chain risks implying
   integration among distinct products. The proposed Power Platform artifact,
   configuration, and data lanes explain a specific engineering mechanism, but
   remain a design proposal. No official icon archive was ingested or rendered.

### Refinement and Targeted Retest

The profile now requires sentence-level claim/URL/locator mapping, repeated pending
foundation qualification, bounded quantifiers, distinct fact/proposal labels,
managed-versus-unmanaged recovery precision, and no ordinary-variable secret-store
recommendation. The builder now explicitly tests rejection of a forced ready state.

The [refined raw replay](instruction-replay-refined.txt) covers Q01, Q07, Q08,
Q09, Q13, Q14, Q20, E01, E03, A04, A05, and A08. Inspection finds the targeted
defects addressed in those written answers: mapped references, bounded operation
scope, no invented stages or universal canvas requirement, conditional recovery,
and no invented pilot approvals or ACP integration. Their narrow response criteria
pass this qualitative review. The other 19 cases were not rerun after refinement;
there is no new 31/31 result and no causal benchmark of improvement.

The targeted dispatch also supplied explicit defect reminders, so this was an
assisted regression replay, not a blind generalization test. Repeated instructions
may have contributed to the better answers. A blind native-host run remains needed.
The revised profile itself was not edited after this targeted replay.

The first named Explore invocation succeeded. A subsequent named invocation failed
because Explore was unavailable; a separate default-agent invocation then returned
the refined report. That report says separate-subagent execution was unverified
from its own context; the parent dispatch establishes it occurred. Neither report
is a native invocation of the Power Platform profile. Tool restrictions were read
as instructions, not tested through attempted host permission enforcement.

## Required Enhancements

1. Implement authenticated, digest-bound approval and DomainReady certification;
   retain rejection of unapproved transitions. Demonstrate native/SDK execution
   with an actual bounded repository task and executable tests before claiming
   SWE capability. ACP/MCP remain separate unimplemented integration work.
2. Complete source capture, date/revision verification, foundational review and
   selected asset rights/sanitization. Add official SDK examples and test guidance
   for the next actual engineering task, not a broad unsupported expertise claim.
3. Run independent blind evaluation against the final digest and tool policy,
   including claim entailment and attempted forbidden actions. Do not accept
   evaluator self-awarded grades without inspecting the answers.
4. After agent approval and separate content/voice/style decisions, render three
   full-resolution style frames showing the app, identical promoted artifact,
   target configuration and separate data migration. Use unchanged approved icons,
   readable labels and no visually implied integrations lacking evidence.
5. Produce and inspect the pilot, then the final MP4. Compare matched checkpoints
   at full size and in motion against the original sheets/videos; measure timing,
   subtitle fit, motion, audio alignment and codec output, then obtain editorial
   acceptance. Only that evidence can support a visual-quality improvement claim.

The current result improves inspectability and exposes prompt defects. It does not
yet demonstrate the requested complete domain-SWE-agent-to-video experience.
