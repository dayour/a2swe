Datadog for Claude Cowork. Observability by conversation.

The Datadog plugin and connector let Claude query Datadog logs, metrics, traces, dashboards and monitors through the Datadog MCP Server.

Decision: Pilot the Datadog connector with one team, keep Datadog permissions scoped, and treat the Preview status as a rollout risk.

Section 1

A bridge. Not a dashboard.

The Datadog MCP Server links your observability data to any agent that speaks the Model Context Protocol, so you ask instead of clicking through screens.

Supported claims

  • The Datadog MCP Server bridges Datadog observability data to AI agents, so logs, metrics, traces, dashboards and monitors can be queried in natural language. [ev-01] [ev-02]

Assets

Speaker notes

Explain that the plugin is a bridge to Datadog data for MCP agents.

Section 2

Where it runs. Cowork and Claude Code.

Claude, including Cowork, uses the official connector. Claude Code installs the plugin from the official Anthropic marketplace.

Supported claims

  • For Claude, including Claude Cowork, the official Datadog connector is the recommended path and includes MCP Apps for in-product visualizations. [ev-05]
  • Claude Code installs the Datadog plugin from the official Anthropic Plugin Marketplace; the plugin bundles the MCP Server with skills and auto-updates. [ev-06]

Assets

Speaker notes

Show the path from Datadog data to the team through the connector or plugin.

Section 3

Set up. Pick a site, sign in.

Choose your Datadog site and sign in with OAuth. Keys are supported, and older manual servers or custom connectors should be removed first.

Supported claims

  • Setup asks you to choose a Datadog site and sign in with OAuth in the browser; API and application keys are a supported alternative. [ev-07] [ev-08]
  • Remove any separately registered Datadog MCP server or custom connector first to avoid conflicts. [ev-14] [ev-15]

Assets

Speaker notes

Walk through the guided setup and the conflict warning.

Section 4

Access. Your permissions still apply.

You need Datadog permissions for the resources you query, and no Datadog credentials are sent to the model provider.

Supported claims

  • You need Datadog permissions for the resources you query, and the plugin states that no Datadog credentials are sent to the AI model provider. [ev-10] [ev-09]

Assets

Speaker notes

Stress that the plugin does not widen access.

Section 5

Control. Choose the toolsets.

Enable or disable groups of MCP tools so the agent sees only the Datadog products your team needs.

Supported claims

  • Groups of MCP tools can be enabled or disabled with the toolsets command. [ev-11]
Speaker notes

Recommend starting with one narrow toolset.

Section 6

Risk. Preview, compliance, site limits.

The plugin is in Preview. The server is HIPAA-eligible, but you own compliance for connected tools, and the government sites are unsupported.

Supported claims

  • The Datadog plugin and its marketplace listing are in Preview. [ev-03] [ev-04]
  • The Datadog MCP Server is HIPAA-eligible, customers remain responsible for the compliance of the AI tools they connect, and the server is not supported on the Datadog government sites. [ev-12] [ev-13]

Assets

Speaker notes

Close with the pilot recommendation and the preview caveat.
