# Revisions and follow-ups

## Revision procedure

1. Read the delivered `agent/SWE_AGENT.md` before editing.
2. Verify that every referenced artifact still exists.
3. Refresh claims whose truth may have changed.
4. Identify the earliest affected lifecycle stage.
5. Invalidate and regenerate dependent outputs.
6. Preserve the released movie and create a new versioned render.
7. Update QC, delivery notes, and companion state.

## Change impact

| Change | Earliest typical restart |
| --- | --- |
| Source correction | Research |
| Spoken wording or pronunciation | Narration and timeline |
| Shot concept with unchanged words | Storyboard |
| Shared color, typography, or overlay behavior | Overlays and primitives |
| Scene implementation defect | Pilot/build group |
| Encoder-only issue | Render |
| Documentation or handoff omission | Delivery |

Narration changes require renewed approval, regenerated speech or supplied audio, fresh timing, subtitle alignment, storyboard review, rerendering, and QC.

## Follow-up videos

A follow-up is a separate project with a new approval record and release inventory. Reusable facts, primitives, and assets can carry forward only with their original provenance and licensing. Prior approval does not transfer to new narration or new external data handling.

## Durable state

The portable companion and versioned project artifacts are the durable state. Chat history alone is not a valid production record.
